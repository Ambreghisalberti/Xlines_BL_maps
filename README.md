# Xlines_BL_maps

Minimal code to go from spacecraft data to the magnetopause boundary layer (BL) dataset, BL flow maps,
the reconnection X-line, its parametric dependence and its comparison with models.

This repo is a **first, verbatim extraction** of the code that produced the final results: the notebook cells are copied
unchanged from the original notebooks (see `PROVENANCE.md` for the origin of every cell and every change), and the
functions come from the `swapp` and `UTime` packages (only the functions that are used). No cleaning has been done yet.

Satellites: MMS1, THEMIS A–E, Cluster 1 and 3.

## Where files are written

All outputs go under `OUT` (`blxline/paths.py`, or the environment variable `BLXLINE_OUT`). Default: `/DATA/ghisalberti/BL_Xline_minimal_outputs`
on kaa, else the folder `data/` of the repo (not versioned). The original files are never overwritten. Model X-lines are read
from `MODEL_LINES` (variable `BLXLINE_MODEL_LINES`; default `/home/ghisalberti/komar_separators` on kaa, else `data/model_xlines/`).

## Data

The datasets are published on Zenodo: [10.5281/zenodo.20312678](https://doi.org/10.5281/zenodo.20312678) (too large for GitHub).
`blxline.data.download(name, folder)` downloads a file and checks it.
- `BL_dataset_multisat_limited.pkl` (1.1 GB): the map dataset **of the paper** (output of step 4; the same file as
  `BL_data_for_maps_without_cusps_withoutNp<3_all_sat_1min_2025-05-06.pkl` used for the paper). Input of
  `07_interactive_xlines.ipynb` (set `DOWNLOAD = True` there to download it into `OUT`). To run `05_maps_and_xline.ipynb`
  with it, save it in `OUT` as `BL_data_for_maps_without_cusps_withoutNp<3_all_sat_1min_2025-05-06.pkl`.
- `BL_dataset_multisat.pkl` (19 GB): the full BL dataset (output of step 3).
- `coldions_multisat.pkl` (1 GB): the cold ions dataset.

On kaa, `OUT` also contains a newer map dataset (`BL_data_for_maps_...pkl` in `OUT`), predicted with the final model on all
satellites (the paper dataset mixes several prediction models, see `PROVENANCE.md`). It is not published yet.

Open the notebooks with the `space` kernel and run them in order. `tools/` contains the scripts used to build the notebooks from
the original ones (`build_notebooks.py`, `spec.json`) and to check that they give the same results (`run_nb.py`, `compare.py`).

## Your own maps and X-lines (`07_interactive_xlines.ipynb`)

New code (`blxline/xlines.py`), not copied from the original notebooks: it chains the functions used for the paper, and with the
paper parameters it gives the same X-lines (checked in the notebook, and for the 182 X-lines of the paper grid). Choose the IMF clock
angle, the tilt, any other column of the dataset, the number of neighbours, the distances and the smoothing with sliders; keep
several lines on the same plot; show the Delta Vz map (optional) and a 3D view.

Every result has a key made of the dataset fingerprint (sha256 of the file) and all the parameters. Before computing, two caches
are searched:
- `xline_cache/` (in the repo): shared X-lines, among which the whole grid of the paper (CLA 120°–180° every 5°, tilt -30°–30°
  every 5°, and CLA alone), for the Zenodo dataset and for the newer dataset of kaa (each result is only used with its own
  dataset). `xline_cache/lines/*.json` are small text files (a few kB each). `calc.share()` copies your own
  X-lines there, to be committed. `mp_grid_N100.npz` is the grid of the maps (saved because it takes 30 s to compute).
- your personal cache (`OUT/xline_cache_personal/`): everything you compute, with the Delta Vz maps (`maps/`, about 100 kB each,
  not shared).

`XLINE_CODE_VERSION` in `blxline/xlines.py` must be increased if the computation changes, so that old results are not reused.
